# 前端代码审计与布局重设计（2026-09）

> 范围：`web/src` 全部 React 代码（10 路由 + 组件层 + 样式系统）
> 结论先行：**前端基础质量高于平均水平，不需要推倒重来**。设计 token、共享原语、页面骨架都已成型；
> 真正的问题集中在「首页信息密度错配」和「顶栏浪费」两处，布局重设计是局部手术，不是大改。

## 一、审计结论

### 做得好的（保持不动）

1. **样式系统**：`index.css` 用 oklch + CSS 变量定义 light/dark 双主题，Tailwind v4 `@theme inline` 映射，主题切换零成本。
2. **共享原语**：`components/layout.tsx` 的 PageHeader / SectionCard / EmptyState / StatTile / Avatar / Field 统一了页面节奏，头像配色按 id 哈希稳定。
3. **人物详情页已分治**：概览（做）/ 画像（理解）/ 关系与组织（维护）三个 tab，高频在前、破坏性操作（删除人物）沉底，符合「频率分层」原则。
4. **记一笔全局抽屉**：QuickRecordModal 从任意页面唤起，选人→写→提交一屏完成，支持连续记录与「记录并提问」。
5. **状态管理克制**：无全局状态库依赖，每页自取自管；错误/加载态统一走 ErrorNote/Spinner。
6. **注释质量高**：几乎每个关键决策都有「为什么」注释（如 scroll remount、手动改过的记录重提需确认）。

### 问题清单

| 级别 | 问题 | 位置 | 说明 |
|---|---|---|---|
| P1 | 首页「今天」名不副实 | `routes/Home.tsx` | 五个统计块全是**全量累计数**（人物总数、记录总数…），对每日决策零信息量；「最近动态」只有 3 条固定槽位。首页没有一件「今天要做的事」 |
| P1 | 顶栏大面积空置 | `App.tsx` header | 顶栏右侧只有「记一笔 + 主题切换」，左侧完全空着。人物一多，**没有全局搜索**，找人要先去人物与组织页 |
| P1 | 空状态重复渲染 | `Home.tsx` 底部 / `PersonDetail.tsx` 底部 | PersonDetail 概览 tab 内已有「还没有记录」提示，页面底部又渲染一遍同样的 EmptyState（735-743 行）；Home 的底部兜底空态与卡片内空态同理 |
| P2 | Organizations 单文件过重 | `routes/Organizations.tsx` | 组织 CRUD + 人物 CRUD + 筛选 + 任职全在一个文件（约 500 行），两个领域实体耦合，后续加功能只会更肿 |
| P2 | 错误提示形态不统一 | 多页 | 有的用 ErrorNote 常驻块，有的用 Notice 三秒消失（flashNotice），同类反馈两种形态 |
| P2 | 时间显示混用 | `Home.tsx` | `dayOf()` 截取日期与 `relativeTime()` 相对时间在同类列表里混用 |
| 备注 | 跟进无全局页 | — | **设计意图，非缺陷**：跟进以人物维度内嵌在详情页，事件记录已覆盖需求，不再单列一级入口 |

### 已核对、无需处理的疑点

- 信息架构文档中「记一笔锁在首页」的问题已修复（全局抽屉）。
- PersonDetail「杂物抽屉」问题已通过三 tab 分治解决。
- 导航分组（日常/关系/回顾/系统）频率分层合理。

## 二、布局重设计（本轮落点）

只动三处，其余保持：

1. **首页改成真正的「今天」**：累计数字块撤掉，换成「最近记录时间线（主栏）+ 最近联系人（右栏）」，
   顶部一句问候 + 记一笔。让首页回答「我最近跟谁接触了、谁快被遗忘了」，而不是「系统里有多少行数据」。
2. **顶栏加全局搜索（⌘K / Ctrl+K）**：搜人物直达详情页，这是人物数量增长后的刚需。
3. **清理重复空态**、统一反馈形态（错误用常驻 Note、成功用轻提示）。

高保真原型见：`docs/前端布局重设计原型.html`（可交互，含暗/亮主题切换）。
