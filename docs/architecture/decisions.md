# 架构决策记录（ADR）

记录 Loom 的重要技术决策及其理由。新增决策追加在文末，不修改历史条目。

## ADR-001 单体单二进制部署

- **状态**：已接受
- **背景**：单人本地使用，吞吐量极低。
- **决策**：Go Echo 单服务 + `go:embed` 嵌入 React 构建产物，交付一个二进制 + 一个 `data` 目录。
- **后果**：部署成本接近零；代价是所有模块同进程，需要靠内部边界（见 ADR-005）防止腐化。

## ADR-002 SQLite + sqlite-vec，单连接

- **状态**：已接受
- **背景**：事实数据与向量检索同库最简单；SQLite 单写。
- **决策**：`modernc.org/sqlite`（纯 Go，零 CGO），WAL + 外键 + 版本化迁移（`schema_migrations`），`SetMaxOpenConns(1)`；向量用 sqlite-vec 虚拟表，初始化失败降级为「无语义检索」，不阻断启动。
- **后果**：无外部依赖；备份即复制单文件（WAL 需注意 checkpoint）。扩展写吞吐不可行，但个人使用场景足够。

## ADR-003 事实与派生数据分离

- **状态**：已接受
- **背景**：AI 产出不可靠且可重算。
- **决策**：`events.raw_text` 是唯一事实来源；summary/traits/建议/报告均为派生物。traits 带来源事件指纹（`source_stale`），建议带逐条结论证据（`evidence_version` 内容指纹），报告先聚合事实再让模型叙述。人工修订置 `manually_edited`，重试需显式 force。
- **后果**：AI 失败不丢数据；代价是 schema 和查询较复杂。

## ADR-004 明确不做的事（v1 边界）

- **状态**：已接受（部分条目被 ADR-006/007 修订）
- **决策**：不做多用户/权限/登录；不做聊天软件导入、OCR；不做移动端；不做 Docker/K8s；不做 LangChain 类框架。
- **后果**：产品保持单人本地工具形态。安全边界因此依赖「只监听本机 + 本地文件权限」，见 ADR-008。

## ADR-005 模块化单体内部边界

- **状态**：已接受（2026-09 阶段 1 改造）
- **背景**：`cmd/server/main.go` 曾集中全部装配，模块间依赖方向不明。
- **决策**：装配抽离到 `internal/app`（`app.go` 装配依赖，`router.go` 注册路由与静态资源），`main.go` 只做启动/信号/关闭。分层保持 handler → service → repository；禁止 service 拼 HTTP 响应、handler 写业务规则。
- **后果**：`main.go` 从 ~240 行降到 ~70 行；后续模块化（domain/ports 拆分）在此基础上渐进进行。

## ADR-006 AI 提取异步任务化

- **状态**：已接受（2026-09 阶段 2 实施）
- **背景**：README v1 明确「不做异步队列，同步 3-15 秒可接受」。实际使用中模型超时/故障直接阻塞创建请求，且无重试与幂等保障。
- **决策**：`POST /api/events` 只写事实行（pending）并立即返回 201（`report.async=true`）；提取、Embedding、画像刷新进入 `internal/tasks` 进程内队列，单 worker 串行执行（SQLite 单连接，并行无益），带状态、退避重试、目标去重与优雅停机。worker 复用 `RetryExtraction`，天然幂等且不覆盖人工修订。启动时把遗留 pending 记录重新入队——队列状态仅存内存，数据库 pending 行才是事实来源，崩溃/重启最多丢失排序，不丢工作。`llm.async_extract: false` 可回退同步模式。
- **语义边界**：LLM 调用失败被 `RetryExtraction` 处理为业务级部分成功（事件行记 `failed` + 错误，不清空原内容），不触发队列自动重试——「提取失败是可见状态，重试由用户决定」是产品约定（README §7.2）。队列级退避重试只针对基础设施错误（如数据库故障）。可观测性：`GET /api/tasks`。

## ADR-007 数据备份与恢复能力

- **状态**：已接受（2026-09 阶段 3 实施）
- **背景**：README v1 写明「不做数据导入导出」。但本工具保存的是不可再生的关系记忆，单文件 SQLite 是单点。
- **决策**：快照用 `VACUUM INTO` 写临时文件后原子改名（WAL 下也是一致快照），保留数轮换；调度器随进程运行，启动约 15 秒后做当日首次快照，失败写入 `GET /api/backups/status` 的 `last_error`——备份缺口必须可见。JSON 导出分完整/脱敏两档：脱敏在序列化前清空原文、画像正文、建议与报告内容并替换姓名，敏感字节不出进程。恢复两阶段：先 `integrity_check`/核心表/迁移版本/外键四项校验，通过后暂存 `<db>.restore-pending`，**下次启动**打开连接前原子换入——运行中换库会让所有仓库层连接作废，属于伪修复。`vec_memory` 缺失只警告不阻断，恢复后用 `POST /api/ai/reindex` 重建。
- **后果**：数据可自证可恢复；代价是恢复需一次重启。定时演练（新目录启动→恢复→验证）纳入阶段 6 运营。

## ADR-008 安全边界与隐私默认

- **状态**：已接受（2026-09 阶段 4 实施）
- **背景**：无认证系统，数据高度敏感；v1 依赖「只监听本机」的隐式假设，一旦绑定 LAN 即裸奔。此外日志曾可能带出记录原文，云端端点的数据出境没有任何显式开关。
- **决策**：
  1. **访问控制**：`server.auth_token` 非空时，所有 `/api` 路由要求令牌（`X-Auth-Token` / `Authorization: Bearer` / `?token=`，常量时间比较，fail closed）。前端弹一次性令牌门，令牌只存浏览器 localStorage；SPA 本身不设防，保证页面能加载出来要令牌。令牌不回显、不进 `/api/config` 响应（json 标签 `-`）。
  2. **数据边界**：`llm.allow_remote: false` 时，所有到非回环端点的模型调用直接失败（chat 与 embeddings 双路检查，fail closed）——提取 prompt 必然携带记录原文，非本机端点即数据出境。该开关只归 config.yaml，设置页 PUT 不重置。
  3. **备份加密**：`backup.passphrase` 非空时快照以 AES-256-GCM（PBKDF2-SHA256，210k 迭代，随机盐）加密为 `.db.enc`，明文中间产物立即销毁；校验/恢复路径透明解密，暂存文件必须为明文 SQLite。口令 json 标签 `-`。
  4. **审计**：迁移 v9 建 `audit_log`；中间件记录全部变更请求与整库导出（method/path/status），`GET /api/audit` 可查。审计写失败只告警不阻断业务。
  5. **可见性**：`GET /api/config` 附带 `privacy` 面板（监听地址、AI 端点是否外部、原文必然发送、边界开关、令牌/加密是否开启），前端设置页展示——安全状态必须是陈述事实，不是阅读源码。
  6. **日志**：rosetta SDK 日志限 warn 级，debug 级请求负载（含关系文本）不落盘。
- **后果**：LAN 暴露从静默风险变为显式选择且可选保护；代价是云端用户需理解 allow_remote 的含义（错误信息已给出指引）。

## ADR-009 API 契约固定与性能护栏

- **状态**：已接受（2026-09 阶段 5 实施）
- **背景**：前后端协作靠「当前 JSON 形状」的默契，路由变更没有机器可校验的防线；分页 limit 无上限、图谱一次性全量，数据增长后前端会成为第一个受害者。
- **决策**：
  1. **契约测试**：`internal/app` 契约测试把 Echo 路由表固化为 `routes.golden.txt`（全量 /api 路由），任何路由增删都必须显式重新生成并同步 `docs/architecture/api.md`，否则测试失败。错误包络 `{ok:false, error:{code,message}}` 与 `X-API-Version` 头也有断言。
  2. **版本策略**：v1 即当前 `/api`；每个响应带 `X-API-Version: 1`；不兼容变更去 `/api/v2`，v1 保留弃用期。单用户本地产品不引入 URL 版本前缀的重负。
  3. **分页护栏**：显式 `?limit=` 超过 500 钳制（`MaxPageLimit`）；`limit<=0` 保留「不分页全量」的既有契约——个人规模全量列表仍便宜，静默截断反而撒谎。审计日志维持自身 100/500 语义。
  4. **图谱护栏**：`GET /api/graph` 人物节点默认 1000、硬上限 5000；超出时 `nodes_total`/`truncated` 明示，前端显示截断横幅——半张图谱必须看起来像半张。
  5. **队列指标**：`GET /api/tasks` 返回 `{tasks, stats}`，stats 含生命周期计数（enqueued/succeeded/failed）、当前深度与运行耗时（last/avg）——失败率是数字，不是印象。
  6. **慢请求告警**：超过 15 秒的请求写 warning 日志（含 method/path/状态/耗时）；同步 AI 端点慢是预期，日志抓意外。
  7. **大数据量回归**：repository 级测试灌注 2000 人物 / 6000 记录 / 3000 跟进，断言分页查询 1 秒预算内完成且总数诚实——索引丢失或 N+1 在 CI 阶段现形。
- **后果**：契约漂移、索引退化、队列静默失败从「上线后用户发现」变为「测试阶段失败」；代价是每次改路由要多一次金样再生成，属于故意添加的摩擦。

## ADR-010 发布管线与数据治理

- **状态**：已接受（2026-09 阶段 6 实施）
- **背景**：改造完成后系统进入长期使用期。此前的测试、构建、冒烟是手动逐条执行的，恢复演练只做过一次；孤儿向量、审计日志增长等数据卫生问题没有机制兜底。
- **决策**：
  1. **单一发布管线**：`scripts/release.ps1`（Windows）/ `release.sh`（POSIX）一次命令完成 vet → 全量测试（金样契约在此强制生效）→ 前端构建 → 后端构建 → 临时库迁移冒烟（真实二进制启动、断言版本头 / 404 包络 / 维护端点）。任何一步失败即非零退出，不产出半成品。
  2. **月度恢复演练**：`scripts/drill.ps1` / `drill.sh` 在临时目录全链路演练——建数据 → 快照 → 校验 → 删除 → 两阶段恢复 → 重启验证。不接触真实数据，通过标准是最后一行 `DRILL PASSED`。每月至少一次；任何改动涉及备份/恢复/迁移路径后加跑一次。
  3. **发布检查清单**：`docs/RELEASE.md` 固化检查项、数据库迁移检查与回滚方案（回滚 = 从快照恢复，不做 schema 降级）。
  4. **数据治理**：`MaintenanceService` 每次启动执行一遍数据卫生（可 `POST /api/maintenance/cleanup` 手动触发并返回报告）：清理孤儿向量（person/event/trait 已不存在的 vec 行，未知 chunk 类型一律不动）；审计日志默认永久保留，`maintenance.audit_retention_days` 显式配置后按窗口修剪。失败提取任务不需要清理——队列历史自剪 500 条上限，失败的记录保留原文（原文是事实，不是垃圾）。
  5. **演进边界重申**：没有数据证明之前不引入微服务、消息中间件或复杂权限系统；SSE、全文检索、更强本地模型按真实使用情况再评估（见计划书阶段 6）。
- **后果**：发布、演练、数据卫生都从「记得手动做」变为「跑一条命令 / 自动发生」；代价是临时目录演练占用几十秒，可忽略。
